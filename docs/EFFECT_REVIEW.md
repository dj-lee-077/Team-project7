# EFFECT_SCENARIO 비교 및 1차 적용

## 적용 기준

EFFECT_SCENARIO.md는 효과 가이드로 읽었습니다. 기존 사용자 결정인 자유 탐색, 숫자 없는 진행 표시, 발견 후에도 유지되는 두 배 밀도의 빛가루, B급 인트로, 상자의 실루엣 생략, 기존 팀원 연결과 대사 수정 대기 상태를 우선합니다. 문서 예시의 자전거·상자 팀원 소개, 실제 소주병 공개, 안경 튜토리얼 강제, 엔딩은 확정된 기획을 바꾸지 않습니다.

## 1. 이미 구현된 기능

- 하나의 원본 이미지와 상대 좌표 Hotspot, PC 클릭·키보드·모바일 터치
- B급 인트로 및 대화창, 입장 후 자유 탐색
- 물체 주변의 비동기 빛가루 및 hover 강조, 발견 후에도 빛가루 유지
- 대상 위치 기준 650ms 줌, 배경 blur(6px)와 brightness(.55), 별도 이벤트 이미지 레이어
- 이벤트 중 배경 입력 차단, 닫기와 Escape, 포커스 처리
- 실루엣 → 대사 → 공개 → 소개 구조, 상자 예외
- 마지막 대사 완료 시 발견 처리, 중단 시 미발견 유지, 재방문 시 공개·설명만 표시
- 학장님 조사 후 술병 Hotspot 활성화, 네 아이템 완료 후 엄지 활성화
- 모션 감소 설정과 새로고침 시 진행 초기화

## 2. 가이드 대비 부족한 요소

1차 적용 전에는 타이핑, 실루엣의 확대 등장, 공개 순간의 별도 강조가 없었습니다. Item Found 보상 단계, Guess 선택지, BAG, 일정 시간 후 힌트, 엄지 해금 전 대화·지연, 시작 대화, 사운드·엔딩도 없습니다.

이미지 완성도는 효과와 별개입니다. 자전거 외 실루엣, 인물 반전 합성 이미지, 학장님 발 주변 상세 이미지, 상자 내부 이미지는 미제공 상태입니다. 안경은 원본 크롭으로 공개되고, 상자는 임시 회전·비어있음 표시입니다. 이미지 준비 중 표시는 이번에도 그대로 남습니다.

가이드의 숫자 HUD, 발견 후 Sparkle 제거, 기본 탐색 Particle 금지는 기존 사용자 결정과 충돌하므로 누락 버그로 보지 않고 적용하지 않습니다.

## 3. 기존 코드에 바로 추가 가능한 효과 / 이번 적용

- 35ms마다 한 글자씩 대사 출력. 출력 중 입력하면 해당 문장을 즉시 완성하고, 다음 입력에서 다음 단계로 넘어갑니다.
- 실루엣이 opacity 0 → 1, scale .85 → 1로 450ms 동안 등장합니다.
- 첫 공개 시 기존 이벤트 이미지가 작게 확대되었다가 제자리로 돌아오며 주변에 짧은 빛이 나타납니다.
- 술병·엄지 공개에는 이미지 레이어만 최대 3px 흔들립니다. 전체 화면은 움직이지 않습니다.
- 같은 이미지를 유지하는 후속 대사에서는 공개 효과를 반복하지 않습니다. 재방문은 공개 효과를 생략합니다.
- 상자에는 화려한 공개 효과를 추가하지 않아 기존 개봉과 허무한 빈 상자 표현을 유지합니다.
- 모션 감소 설정에서는 글자를 바로 표시하고 신규 확대·흔들림·빛 효과를 생략합니다.

Hotspot 위치, 이미지 배치, 메인 사진, 기존 대사와 발견 조건은 변경하지 않았습니다. 타이핑 중 닫기나 재진입 시 이전 타이머가 새 대사를 덮어쓰지 않도록 취소합니다. 화면 읽기 프로그램에는 글자별 갱신 대신 완성된 대사를 버튼 이름으로 제공합니다.

## 4. 구조 확장이 필요한 기능

| 기능 | 필요한 확장 |
| --- | --- |
| Guess 및 상자 선택지 | 대사 데이터에 choices/분기, 선택 UI, 포커스 및 재시도 규칙 |
| 소개 전 Item Found | 공개와 발견 완료의 시점 구분, 전용 보상 단계, 도중 닫기 처리. 현재는 마지막 대사를 마쳐야 발견 완료 |
| BAG | 별도 열기·닫기 화면, 미발견 정보 숨김, 기존 재방문 진입 연결 |
| 엄지 해금 전 뜸 들이기 | 조건 충족과 클릭 가능 시점 분리, 취소 가능한 해금 시퀀스 |
| 시작 대화·엔딩 | 아이템에 속하지 않는 공통 대화 흐름과 기획 대사 |
| 사운드 | 사운드 사용 결정, 에셋, 사용자 입력 후 재생·음소거 상태 |

## 5. 구현 우선순위

1. 완료: 타이핑 + 실루엣 등장 + 국소적인 공개 피드백. 데이터와 상태 머신을 보존하는 작은 변경입니다.
2. 다음: 숫자 없는 발견 보상, 엄지 해금 전 짧은 연출. 발견 완료 및 중단 규칙과 함께 확장합니다.
3. 이후: Guess/상자 선택지와 BAG. 먼저 선택지 내용·분기 정책을 확정해야 합니다.
4. 마지막: 실제 이미지·대사 통합 후 상세 전환, 힌트, 사운드 및 미정 엔딩.

JavaScript 구문 검사, 기존 발견/해금/재방문 상태 검사, 가상 타이머로 타이핑 완료·취소·교체 검사, 실제 script.js와 상태 모듈을 연결한 입력·중단·재진입·재방문 검사를 수행합니다. 이번 단계는 실제 브라우저의 시각 QA를 수행하지 않았습니다.
